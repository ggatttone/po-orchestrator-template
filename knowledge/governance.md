# Governance Model

## Governance Layers

| Layer | Audience | Cadence | Focus | Decision authority |
|---|---|---|---|---|
| **Steering Group** | Executive sponsors, program director | Monthly | Strategic direction, budget, go/no-go | Program scope, budget, timeline |
| **Program Board** | Program manager, POs, architects | Bi-weekly | Cross-team coordination, blockers, priorities | Epic prioritization, resource allocation |
| **BO Community** | Business Owners, process owners | As needed | Requirements validation, process decisions | Business rules, process design |
| **Core Team** | PO, developers, consultants, testers | Daily/weekly | Sprint work, impediments, technical decisions | Implementation approach, story details |

## Communication Standards

| Audience | Tone | Length | Format |
|---|---|---|---|
| Steering Group | Executive, strategic | 1 page max | Status report (monthly) |
| Program Board | Professional, detailed | 1-2 pages | Sprint review notes (bi-weekly) |
| BO Community | Collaborative, business-focused | 1 page | Workshop / alignment update |
| Core Team | Direct, operational | 0.5-1 page | Standup / planning notes |

## Decision Authority Matrix

| Decision type | Who decides | Who is consulted |
|---|---|---|
| Program scope change | Steering Group | Program Board |
| Epic prioritization | Program Board | POs, BOs |
| Requirements approval | Business Owner | PO, Consultants |
| Sprint scope | PO + Team | BO |
| Technical approach | Solution Architect | PO, Developers |

## Escalation Path

1. **Core Team** -> PO resolves within sprint
2. **PO -> Program Board** -> Cross-team or resource issues
3. **Program Board -> Steering Group** -> Budget, timeline, or strategic blockers
