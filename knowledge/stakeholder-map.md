## Role Definitions

| Role | Responsibility | Typical governance layer |
|---|---|---|
| **Business Owner (BO)** | Accountable for process domain, approves requirements and scope | BO Community |
| **Product Owner (PO)** | Translates business needs into stories, prioritizes backlog | Core Team / Program Board |
| **Solution Architect** | Designs technical approach, validates feasibility | Core Team / Program Board |
| **Consultant** | Domain expertise, configuration, implementation | Core Team |
| **Thema Lead** | Coordinates work across related epics | Program Board |
| **Program Manager** | Cross-team coordination, resource allocation | Program Board / Steering |

## Engagement Matrix

| Stakeholder Type | When to involve | How to communicate |
|---|---|---|
| BO | Requirements approval, scope changes, process decisions | Workshop, 1:1 meeting |
| Architect | Technical feasibility, integration design, baseline analysis | Technical review, Jira comments |
| Consultant | Configuration questions, domain-specific scenarios | Email, workshop |
| Program Manager | Cross-epic blockers, resource conflicts, timeline issues | Status update, escalation |
